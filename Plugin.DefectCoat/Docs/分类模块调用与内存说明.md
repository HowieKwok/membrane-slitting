# 分类模块：位置 / 调用链 / 内存生命周期

## 1. 模块在哪里

| 文件 | 作用 |
| --- | --- |
| `DefectRuleClassifier\Core\Classifiers\OnnxModelClassifier.cs` | ONNX 分类器本体（每个实例独立会话，线程安全，不依赖 HALCON） |
| `DefectRuleClassifier\Core\Classifiers\ModelClassifierConfig.cs` | 分类器配置 + 序号绑定缓存（O(1) 查表） |
| `DefectRuleClassifier\Core\Models\ModelImageInput.cs` | 与 HALCON 解耦的 RGB 像素输入 |
| `Plugin.DefectCoat\Core\Pipeline\DefectDetectPipeline.cs` | 检测+分类调度主流程 |
| `Plugin.DefectCoat\Models\DefectCoatObj.cs` | 插件对象：`ExecuteObj()` 是检测入口，持有分类器实例 |
| `Plugin.DefectCoat\Views\ClassifierToolWindow`（DefectRuleClassifier） | 完整工具界面：推理 / 测试 / 训练 / 序号绑定 |

## 2. 怎么调用 / 怎么检测（调用链）

```text
宿主(Mef_VisionFrame)
  └─ DefectCoatObj.ExecuteObj()            ← 检测入口（插件“执行检测”）
       └─ pipeline.Run(Params, featureRuleConfig, modelClassifierConfig)
            ├─ detector.Detect(...)         ← HALCON 检测，裁出候选小图 candidate.CropImage
            └─ pipeline.Classify(...)
                 ├─ 特征值分类（EnableFeatureRuleClassify）
                 ├─ 模型分类（EnableModelClassify）：
                 │    BuildModelImageInput(candidate)   ← HALCON 小图 → RGB 像素（只读借用）
                 │    OnnxModelClassifier.Classify(ModelImageInput)  ← 并行 + O(1) 序号查表
                 │    输出：类别 = 绑定标签 / 未绑定 = 涂布不良，携带 序号 + 置信度
                 └─ AI 分类（预留）
```

模型加载：`DefectCoatObj.InitObj()` 里 `modelClassifier.Init(ModelPath, …)`，
同时 `RebuildResolvedLabels()` 构建序号绑定缓存。

手动验证（不依赖宿主）：

- “分类规则设置 → 分类器分类 → 打开分类器工具”：
  - 推理页：选图片 → 推理，看类别/序号/置信度/标注图；
  - 测试页：选测试目录 → 批量测试 → 准确率 + CSV；
  - 训练页：选数据集 → 续接训练（后台隐藏进程）。

## 3. 内存生命周期（已处理项）

| 对象 | 归属 / 释放 |
| --- | --- |
| `candidate.CropImage`（HALCON 小图） | 归候选所有。转换时**只读借用**：本身是 HImage 绝不释放；普通 HObject 包装的 HImage 用完即释放 |
| `Compose3` / `ConvertImageType` 中间图 | 转换产生的**新 HImage** 立即释放 |
| RGB `byte[]`（ModelImageInput） | 每次推理的临时拷贝，随调用结束可回收，无累积 |
| OpenCvSharp `Mat` | 全部 `using` 释放 |
| ONNX Runtime `InferenceSession` | 每个插件对象实例一个；`Dispose()`/插件释放时释放 |
| ONNX Run 输出 / `DenseTensor` | `using` 释放 / 临时对象 |
| `NgDefectResult.CropImage` | 结果对象独立 `CopyObj` 一份；`Dispose()` 统一释放，不影响候选 |
| `Params.NgResults` / 输出 Region | 插件输出副本；下次运行前 `ReleaseOutputHObjects` 清理 |
| 界面预览 Bitmap / BitmapImage | `using` + `Freeze()`，选行/切图时替换释放 |

多任务：每个插件对象独立持有会话与配置副本，两个模块实例并发不共享 HALCON/ONNX 句柄。

## 4. 你自己怎么检查内存问题

在宿主里做“压力检查”：

1. 打开任务管理器/性能监视器，记录进程“工作集(内存)”；
2. 连续执行检测（同一张图跑 50~100 次），观察内存是否**持续单调增长**；
3. 若持续增长：多半是 HALCON 对象或 Bitmap 未释放；
   - 用 HALCON 的 `count_obj` / 内存监控，或任务管理器观察；
   - 常见泄漏点：检测器内部 Region/Image 未释放、Params 输出未清、预览 Bitmap 未释放。
4. 若内存涨到一定值后稳定（GC 曲线起伏），属于正常托管内存波动，不是泄漏。

本插件的转换层已按上表释放；若你在宿主里压测发现增长，优先检查检测器
（`HalconThresholdDefectDetector`）和宿主输出容器，告诉我现象（涨速/是否回落到基线）我再定位。
