# 插件更新与环境部署说明

> 适用：在 `20260807\combine` 解决方案里修改 DefectRuleClassifier / Plugin.DefectCoat 后，
> 重新编译并更新到运行环境。

## 1. 编译顺序（必须先编译分类器，再编译插件）

### 1.1 编译 DefectRuleClassifier（分类器 DLL）

命令行（任选其一）：

```bat
dotnet build "D:\BaiduNetdiskDownload\模切项目合并\20260807\combine\DefectRuleClassifier\DefectRuleClassifier.csproj" -c Release
```

或在 Visual Studio 打开 `Mef_VisionFrame.sln`，右键 DefectRuleClassifier → 生成。

输出：`DefectRuleClassifier\bin\x64\Release\DefectRuleClassifier.dll`

> 该工程是 SDK 风格（net472 + WPF），已引用 ONNX Runtime 与 OpenCvSharp NuGet，
> 首次编译会自动还原包；需要联网。

### 1.2 编译 Plugin.DefectCoat（插件 DLL）

必须使用 VS 的 MSBuild（经典工程才能编译 XAML）：

```bat
"C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" ^
  "D:\BaiduNetdiskDownload\模切项目合并\20260807\combine\Plugin.DefectCoat\Plugin.DefectCoat.csproj" ^
  -p:Configuration=Release -p:Platform=AnyCPU -restore -v:m
```

输出直接进入：`Mef_VisionFrame\bin\Release\Plugins\`

> 工程内置 `CopyClassifierNativeDlls` 目标：构建后自动把
> `onnxruntime.dll`、`onnxruntime_providers_shared.dll`、`OpenCvSharpExtern.dll`
> 复制到插件输出目录，无需手工拷贝原生库。

## 2. 更新软件：要拷哪些文件

把下面这些**从 `Mef_VisionFrame\bin\Release\Plugins\` 一起复制**到目标运行环境的插件目录
（生产机一般也是该目录，覆盖即可）：

| 文件 | 说明 |
| --- | --- |
| `Plugin.DefectCoat.dll` | 插件本体（你改的界面/流程） |
| `DefectRuleClassifier.dll` | 分类器（ONNX 推理、序号绑定） |
| `Microsoft.ML.OnnxRuntime.dll` | ONNX Runtime 托管库 |
| `OpenCvSharp.dll` | OpenCV 托管库 |
| `onnxruntime.dll` | ONNX Runtime 原生库（x64） |
| `onnxruntime_providers_shared.dll` | ONNX Runtime 原生依赖 |
| `OpenCvSharpExtern.dll` | OpenCV 原生库（x64） |

如目标机提示缺 `Newtonsoft.Json.dll` / `CommunityToolkit.Mvvm.dll` / `FrameCommunity.dll`，
一并从 `DefectRuleClassifier\bin\x64\Release\` 或 `Frame_Core\bin\Release\` 复制。

更新步骤：

1. 停止宿主软件（或退出运行中的检测流程）；
2. 备份原 `Plugins` 目录（复制一份到 `Plugins_bak_日期`）；
3. 覆盖上述 DLL；
4. 启动宿主 → 打开“分类规则设置 → 分类器分类”确认模型/绑定还在；
5. 跑一次检测，确认分类结果和内存表现正常。

## 3. 运行环境（目标机需要什么）

### 3.1 必选

| 依赖 | 说明 |
| --- | --- |
| Windows x64 | 10/11 均可 |
| .NET Framework 4.7.2+ | 建议 4.8（Windows 自带） |
| HALCON 20.11 x64 | 检测与裁图使用，需要 DL + HDevelop 授权 |
| VC++ 2015-2022 x64 运行库 | ONNX Runtime / OpenCvSharpExtern 依赖 |

### 3.2 插件自身的配置文件（运行时会读取）

默认位于宿主目录 `Config\Plugin.DefectCoat\`：

| 文件 | 说明 |
| --- | --- |
| `FeatureRuleClassifierConfig.json` | 特征值分类规则（NgTypes 标签） |
| `FeatureRuleClassifierConfig.ModelClassifier.json` | 分类器配置：模型路径、标签路径、序号绑定表、未绑定输出类别 |

模型文件（由训练产出，路径在 ModelClassifier.json 里配置）：

- `model.onnx`（ONNX 模型）
- `labels.txt`（类别名，行序=序号 0 起；支持 UTF-8 / UTF-16 / GBK）

### 3.3 可选（只用“续接训练”时需要）

- Python 3.12（如 `E:\Python312`）
- PyTorch（CPU）、opencv-python、onnx、onnxscript、numpy、pillow
- 训练脚本 `E:\软件代码库\OpenCV分类Demo\train_demo.py`
- 数据集根目录（类别文件夹=标签）

> 推理本身**不需要 Python**；Python 只在界面里点“续接训练”时作为后台进程被调用。

## 4. 常见问题

| 现象 | 处理 |
| --- | --- |
| 运行报 “找不到 onnxruntime.dll / OpenCvSharpExtern.dll” | 没拷贝原生库；按第 2 节把三个原生 DLL 一起拷过去 |
| 报 “OpenCvSharpExtern.dll 加载失败 / DllNotFoundException” | 缺 VC++ 运行库，或混用 x86/x64（必须全 x64） |
| 改了代码但界面没变化 | 覆盖的是旧 DLL；确认已重新编译且复制到实际运行目录，重启宿主 |
| 序号绑定“保存了又没” | 新版已修复：保存绑定后自动通知插件重载；仍出现则确认 DefectRuleClassifier.dll 是最新版 |
| 分类结果乱码 | 确认 labels.txt 编码（UTF-8/UTF-16/GBK 均可，会自动识别） |
| 续接训练点不动 / 报 Python 错误 | 目标机未装 Python 或脚本路径不对（见 3.3） |
